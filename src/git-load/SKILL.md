# 讀檔 Skill — 版本還原

## 角色定位

讓不懂 git 的使用者能安全地回到之前任何一個存檔版本。整個流程像是「翻相簿選一張照片」，使用者只需要選號碼。

## 觸發詞

以下任何說法都會啟動讀檔流程：
- `/讀檔`
- `讀檔`
- `回到之前`
- `之前那個版本比較好`
- `我想回到之前`
- `還原`
- `之前比較好`

## 執行流程

### Step 1：取得歷史紀錄
執行 `git log --oneline -20` 取得最近 20 筆紀錄。

**沒有任何紀錄時（全新專案）：**
回覆：
「目前這個專案還沒有任何存檔紀錄。
你可以先用「/存檔」把現在的進度記錄下來，之後就可以隨時回到這裡囉！」
然後停止。

### Step 2：顯示友善格式清單

**格式規則：**
- 編號從 1 開始（最新的是 #1）
- 時間用相對說法（見下方對照表）
- **絕對不顯示** commit hash 或任何英數字代碼
- 描述直接用 commit message 的文字

**相對時間對照：**
| 時間範圍 | 顯示方式 |
|---------|---------|
| 5 分鐘內 | 剛才（X 分鐘前）|
| 1 小時內 | X 分鐘前 |
| 今天 | X 小時前 |
| 昨天 | 昨天 |
| 2-6 天前 | X 天前 |
| 1 週前 | 上週 |
| 更早 | X 週前 / X 個月前 |

**顯示範例：**
```
以下是你的存檔紀錄，想回到哪一個？

#1  ⏰ 2 小時前
    新增 FAQ 常見問題區塊

#2  ⏰ 5 小時前
    修正手機版按鈕跑版問題

#3  ⏰ 昨天
    加入品牌藍色主題配色

#4  ⏰ 3 天前
    建立客戶問卷推薦工具

#5  ⏰ 上週
    專案初始建立

輸入編號就好（例如輸入 3）。
⚠️ 還原後，那個版本之後的修改會消失，請確認後再選。
```

### Step 3：等待使用者選擇

使用者輸入編號（或描述性文字如「加入藍色配色那個」）。

**如果使用者說描述性文字（如「藍色那個」）：**
根據描述找最符合的那筆，主動說：「你說的應該是 #3 『加入品牌藍色主題配色』對嗎？」

### Step 4：二次確認（重要）

選好版本後，**必須**進行二次確認。重點是讓使用者安心：這個動作是**可逆的**，不會弄丟任何東西。

```
你選擇的是：「加入品牌藍色主題配色」（昨天的版本）

我會這樣做：
1. 先把你「現在」的進度也存一個檔（保險起見）
2. 再把畫面切回「加入品牌藍色主題配色」那個版本

👉 放心，這之後比較新的那些進度（例如「新增 FAQ 區塊」）都還在，
   你之後隨時可以再用「/讀檔」切回去，不會弄丟任何東西。

要切回那個版本嗎？請回覆：
✅「確定」— 切回去
❌「取消」— 保留現在的畫面
```

**如果使用者取消：**
回覆：「好的，目前的進度不受影響 😊 如果之後還想查看存檔記錄，隨時輸入 /讀檔 就可以。」

### Step 5：執行還原（永不丟資料）

使用者確認後，**工匠模式**執行以下兩步，全程不對使用者顯示任何代碼：

```bash
# 1. 先保住現況：若工作區有尚未存檔的變更，自動存一個安全快照
git add -A
git diff --cached --quiet || git commit -m "還原前自動備份：保存當下進度"

# 2. 把目標版本的內容取回主線（不進入游離 HEAD、不丟歷史）
git checkout <hash> -- .        # 取回該版本的所有檔案內容
git add -A
git commit -m "還原到：<該版本的白話描述>"
```

**為什麼這樣做：** 這不是把後面的進度刪掉，而是「把舊版內容複製回來、變成一筆新的存檔」。
所以舊存檔、新存檔通通都在，使用者之後可以再「/讀檔」切回任何一筆。
**絕對不使用** `git reset --hard` 或單獨的 `git checkout <hash>`（會丟資料或進入危險狀態）。

### Step 6：確認結果

```
✅ 好了！畫面已經切回「加入品牌藍色主題配色」那個版本了。

你剛才的進度我也幫你一起存好了，沒有弄丟任何東西。
如果想再換到別的版本（包含剛剛那個比較新的），隨時輸入 /讀檔 就可以！
```

## 語言規則

**永遠不說的詞：**
- git、hash、commit hash、HEAD、detached HEAD
- checkout、reset、branch、merge
- 任何英數字代碼（如 abc1234）

**永遠不做的事：**
- 叫使用者自己輸入任何指令
- 顯示 commit hash 或任何代碼給使用者看
- 跳過二次確認直接執行
- 使用 `git reset --hard` 或單獨 `git checkout <hash>`（會丟資料 / 進入危險狀態）
- 對使用者說修改會「永久消失 / 無法找回」（這是錯的，還原是可逆的）

## 邊界情況

| 情況 | 處理方式 |
|------|---------|
| 沒有存檔紀錄 | 友善提示先用 /存檔，停止 |
| 使用者輸入文字而非數字 | 猜測意圖，確認後繼續 |
| 使用者取消 | 「目前的進度不受影響 😊」 |
| 只有一筆紀錄 | 說「目前只有一個存檔版本，就是現在這個狀態」 |
| 工作區有未存的變更 | 還原前自動存一筆安全快照（Step 5 第 1 步），不打擾使用者 |
| 還原過程出問題 | 說「還原時遇到一點問題，我來看看」，自行修復；因為已先備份，使用者的進度仍安全 |
