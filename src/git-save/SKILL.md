# 存檔 Skill — 智慧版本記錄

## 角色定位

這個 skill 讓不懂 git 的使用者可以輕鬆儲存專案進度。所有技術操作由 AI 自動完成，使用者只看到友善的中文說明。

## 觸發詞

以下任何說法都會啟動存檔流程：
- `/存檔`
- `存檔`
- `儲存進度`
- `記錄一下`
- `先存一下`
- `幫我存檔`

## 執行流程

### Step 1：掃描現況
執行 `git status --porcelain` 查看所有變更。

**特殊情況處理：**
- 專案資料夾沒有 git → 靜默執行 `git init` 後繼續
- 有 untracked 檔案 → 靜默執行 `git add .` 後繼續

### Step 2：判斷是否有修改

**沒有任何修改時：**
回覆：「目前沒有新的修改，不需要存檔喔 😊」
然後停止，不繼續執行。

### Step 3：按功能分組

分析所有修改的檔案，按以下分類歸組：

| 分類 | 判斷標準 |
|------|---------|
| 新增功能 | 新增了新的頁面、功能、工具 |
| 修正問題 | 修掉了 bug、錯誤、跑版 |
| 調整外觀 | 改了顏色、字型、排版、樣式 |
| 更新設定 | 改了設定檔、環境變數、config |
| 整理檔案 | 重新命名、移動、刪除、整理結構 |

### Step 4：生成白話描述

每組生成一句描述。描述要像是在告訴朋友「你做了什麼事」：

**好的描述範例：**
- ✅ 「新增客戶問卷頁面，填完自動推薦方案」
- ✅ 「修正手機版畫面跑版的問題」
- ✅ 「調整首頁配色，改成藍白主題」
- ✅ 「更新 LINE Notify 的連結設定」

**不好的描述範例：**
- ❌ 「update」
- ❌ 「fix bug」
- ❌ 「修改」
- ❌ 「更新檔案」
- ❌ 「add new features」

描述要具體說明「做了什麼」+「目的或效果」，不要只說動作。

### Step 5：執行存檔

```bash
git add .
git commit -m "描述內容"
```

多個分組時，可以合併成一個 commit，描述用分號隔開。
或者按分組各自 commit，視情況選擇較合適的方式。

### Step 6：回報結果

用白話告訴使用者存好了：

```
✅ 存檔完成！這次記錄了以下內容：

📝 新增功能
   新增客戶問卷頁面，填完自動推薦方案

🔧 修正問題
   修正手機版畫面跑版的問題

現在共有 X 個存檔紀錄，隨時可以用「/讀檔」回到之前任何一個版本。
```

## 語言規則

**永遠不說的詞：**
- git、commit、branch、staging area、index、working tree
- hash、HEAD、merge、push、pull
- 任何英文指令

**用這些詞代替：**
- commit → 存檔紀錄
- branch → （不需要提及）
- staging → （不需要提及）
- git log → 存檔歷史

## 邊界情況

| 情況 | 處理方式 |
|------|---------|
| 沒有修改 | 「目前沒有新的修改，不需要存檔喔 😊」 |
| 資料夾沒有 git | 靜默 `git init`，繼續流程 |
| 有 untracked 檔案 | 靜默 `git add .`，一起存進去 |
| git init 失敗 | 說「這個資料夾目前無法使用存檔功能，可能需要先確認一下」 |
