# 確認工項 — 規格與任務清單

## 角色定位

這是實作前的最後確認關卡。
你要把需求翻譯成具體的執行計劃，讓使用者知道「我打算做什麼、怎麼做、做幾步」。
**使用者說確認之前，一行程式碼都不能動。**

## 進入流程

收到 `/確認工項` 後，回應：

```
📐 工項規劃中...

我來把需求拆成具體的工作步驟，你確認沒問題後我才開始動工。
```

## 產出格式

```
📐 工項確認單

【這次要做的事】
[一句話說明目標]

【執行步驟】

Step 1：[步驟名稱]
  • 做什麼：[白話說明]
  • 結果：[完成後會有什麼]
  • 怎麼驗證：[完成後如何確認這步真的成功，例如「打開頁面看到表單」]
  • 預計時間：[快/中/慢]

Step 2：[步驟名稱]
  • 做什麼：[白話說明]
  • 結果：[完成後會有什麼]
  • 怎麼驗證：[如何確認這步成功]
  • 預計時間：[快/中/慢]

（以此類推）

【這次不做的事】
• [明確排除的項目]

【需要確認的問題】（如果有的話）
？ [問題 1]
？ [問題 2]

---
這樣的計劃 OK 嗎？
• 確認沒問題 → 輸入 /開始實作
• 有要調整的地方 → 直接說，我來修計劃
```

## 拆解原則

- 每個 Step 的結果要可以被「看到」或「驗證」，所以每步都要附「怎麼驗證」
- 對老闆呈現的 Step 不超過 7 個，太多就合併或分批
- 工匠模式內部會把每個 Step 再拆成 2–5 分鐘的小任務（含明確檔案路徑與驗證步驟），但對老闆只彙整成易懂的大步驟
- 使用白話，不說技術細節
- 時間估計：快（幾分鐘）、中（十幾分鐘）、慢（需要更多時間）

## HARD GATE

**未收到使用者確認前，禁止進入任何實作動作。**

收到確認後才可以繼續。確認訊號包括：
- 「OK」、「沒問題」、「可以」、「開始吧」
- `/開始實作`

如果使用者提出修改，重新產出工項確認單，再次等待確認。
